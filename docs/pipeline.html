OFFLINE VIDEO PIPELINE · HOW IT WORKS

One JSON spec in, a narrated MP4 out. Code-based, not generative.

Spec
What the video says and shows: scenes, narration, chat blocks, diagrams, captions.
videos/<id>/video.json
Brand
How it looks: wordmark, colours, the product window's chrome.
brand.json
Composition
One HTML page that draws any moment of any video: scene types, motion, layout for both sizes.
engine/comp.html
One command per video
node engine/revoice.mjs videos/<id> builds it the first time, and after an edit re-does only the scenes that changed. A person or an AI coding agent writes the spec, reads the stills back, fixes layout, re-renders.
01 VOICE
Narration
Acronyms respelt and phoneme-checked, then one clip per sentence, synthesised locally on CPU.
Kokoro-82M · kokoro-onnx · espeak phonemiser · ffmpeg resample
02 TIMING
Beat grid
Each clip measured; scenes start on a 100 BPM grid so cuts land on the music, which is synthesised to length.
clip lengths → scene schedule · synthesised score
03 RENDER
Frame by frame
Every frame is a pure function of time. Headless Chrome seeks and screenshots at 30 fps.
DevTools Protocol · 1920×1080 + 1080×1080
04 MUX
Encode
Frames + voice + music to MP4, poster baked in as frame zero.
FFmpeg · libx264 crf 18 · AAC · music −15 dB
05 QUEUE
Batch
Many videos and sizes in parallel. Measured on the original project: 21 videos in 33 minutes on one workstation.
parallel render + encode jobs
No generative video model. No cloud API. Nothing leaves the machine.Node · Python · Chrome · FFmpeg
